# مستندات KnowledgeCoach

این پوشه شامل اسناد مرجع محصول KnowledgeCoach است. هدف این مستندات این است که تعریف محصول، مدل مفهومی، تصمیم‌های تثبیت‌شده، و مرزهای اصلی طراحی به‌صورت شفاف و مستقل از تکنولوژی نگهداری شوند.

این اسناد باید به‌عنوان baseline اصلی محصول در نظر گرفته شوند. هر تصمیم جدید، تغییر محصول، یا شروع توسعه در هر فریم‌ورک و stack جدید باید با این اسناد تطبیق داده شود.

## قاعده مهم در نگهداری مستندات

این مستندات نباید صرفاً آرشیو شوند. هر تغییر مهم در محصول باید در اسناد اصلی منعکس شود. تا زمانی که baseline محصول در حال شکل‌گیری و تکمیل است، تغییرها باید مستقیماً در همین اسناد بازنویسی شوند، نه اینکه بیرون از آن‌ها به‌صورت پراکنده نگهداری شوند.

پس اگر:
- قابلیت جدیدی به محصول اضافه شد
- یکی از تصمیم‌های اصلی تغییر کرد
- مدل دامنه اصلاح شد
- محدوده MVP تغییر کرد

باید اسناد مرجع به‌روزرسانی شوند.

## اصل مهم

حقیقت محصول باید مستقل از implementation باقی بماند.

یعنی:
- این مستندات نباید وابسته به زبان برنامه‌نویسی خاص باشند
- نباید وابسته به فریم‌ورک خاص باشند
- نباید وابسته به ساختار solution فعلی باشند

این استقلال باعث می‌شود اگر implementation stack تغییر کند، فهم محصول و دامنه از بین نرود.
