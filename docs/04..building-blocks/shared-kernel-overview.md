# نمای کلی SharedKernel

## مقدمه
پروژه `KnowledgeCoach.BuildingBlocks.SharedKernel` شامل مفاهیم پایه و مشترک دامنه‌ای است که بین ماژول‌های مختلف پروژه استفاده می‌شوند.

هدف از SharedKernel این نیست که به محل نگهداری هر نوع کد مشترک تبدیل شود.
این بخش فقط باید شامل مفاهیمی باشد که:

- معنی دامنه‌ای پایه دارند
- بین چند ماژول قابل استفاده هستند
- نسبتاً پایدار هستند
- وابسته به یک ماژول خاص نیستند

## اجزای فعلی SharedKernel

### Entity<TId>
کلاس `Entity<TId>` پایه‌ای برای موجودیت‌های دامنه است.

ویژگی اصلی Entity این است که هویت دارد و بر اساس هویت خود شناخته می‌شود، نه صرفاً بر اساس مقدار فیلدها.

در این پروژه:
- مقایسه Entityها بر اساس `Id` انجام می‌شود
- نوع واقعی شیء نیز در مقایسه در نظر گرفته می‌شود

### AggregateRoot<TId>
کلاس `AggregateRoot<TId>` از `Entity<TId>` ارث می‌برد و برای نمایش ریشه aggregate استفاده می‌شود.

در حال حاضر این کلاس:
- از موجودیت پایه ارث می‌برد
- لیستی از domain eventها را نگه می‌دارد
- امکان اضافه کردن و پاک کردن رویدادهای دامنه را فراهم می‌کند

نکته مهم این است که aggregate root فعلاً فقط eventها را collect می‌کند و مسئول publish کردن آن‌ها نیست.

### ValueObject
کلاس `ValueObject` پایه‌ای برای اشیائی است که با مقدارشان شناخته می‌شوند، نه با هویت.

در این پروژه:
- برابری `ValueObject`ها بر اساس اجزای تشکیل‌دهنده آن‌ها محاسبه می‌شود
- هر value object باید `GetEqualityComponents()` را پیاده‌سازی کند

### IDomainEvent
این interface قرارداد پایه برای رویدادهای دامنه است.

فعلاً فقط شامل زمان وقوع رویداد است:

- `OccurredOnUtc`

این interface پایه‌ای برای توسعه بعدی eventهای دامنه در ماژول‌ها خواهد بود.

## چرا این بخش را ساده نگه داشته‌ایم؟
در این مرحله از پروژه، هدف ما ساختن حداقل primitives لازم برای شروع مدل‌سازی دامنه است.

به همین دلیل عمداً این موارد را هنوز اضافه نکرده‌ایم:

- event dispatcher
- outbox pattern
- integration event abstraction
- domain service base classes
- specification pattern
- repository abstractions عمومی

دلیل این تصمیم این است که SharedKernel باید کوچک، پایدار و کم‌وابسته بماند.

## اصل مهم
هر چیزی که مشترک است، لزوماً نباید وارد SharedKernel شود.

به‌طور خاص این موارد نباید بدون دلیل محکم وارد SharedKernel شوند:

- DTOها
- validatorها
- کلاس‌های مربوط به زیرساخت
- abstractionهای خاص application layer
- ruleهای خاص یک ماژول
- قراردادهای API

## جمع‌بندی
SharedKernel در پروژه KnowledgeCoach نقش زبان پایه دامنه را بازی می‌کند.
در این مرحله، فقط اجزایی به آن اضافه شده‌اند که برای شروع مدل‌سازی ماژول‌ها لازم و کافی هستند.

این پروژه باید در ادامه نیز کوچک و کنترل‌شده باقی بماند.
